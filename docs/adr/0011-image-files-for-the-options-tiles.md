# ADR 0011: Image files only for the Options tiles

**Status:** accepted
**Date:** 2026-10-07

## Context

The tiles in Options showed two colour dots (CHE-265). Three styles were tried behind a flag: real renders of the game (image files), pixel icons drawn in code and line icons in code. The owner picked the real renders (CHE-287). The game is otherwise fully procedural and loads no image, model or font files while it runs.

## Decision

**The Theme, World, Sky and Backdrop tiles use small image files, and nothing else does.**

- 17 webp files in `public/tiles/`, named `<kind>-<id>.webp`, 132 px square, 1 to 4 KB each.
- They are generated by `tools/tile-renders.mjs` from the game itself (headless Chrome through `launchBrowser()`), never edited by hand. A look change means running the script again.
- `test/tiles.mjs` (fast tier) fails when an id in the Options rows has no file or a file has no id, and prints the regenerate command.
- The styles with pixel and line icons and the `?tiles=` flag are removed. Light keeps its tiles.
- README and CLAUDE.md state the exception in one line each.
- The pictures preload in idle time once the board takes input (CHE-345, `preloadAllTiles` in `src/themes/tiles.js`, skipped on Save-Data or a 2g connection), so Options shows them at once; the service worker keeps them.

## Rationale

A picture of the real scene shows what a choice is about better than an icon. The files are tiny, they are made by the game, and the staleness test keeps them in step, so the cost is 17 small files and one regenerate step. The exception stays narrow: any other asset file needs its own ADR.
